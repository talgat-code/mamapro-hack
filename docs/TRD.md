# TRD — технический черновик

**Наблюдение, 14.11.2026:** исходный репозиторий пуст, Git инициализирован без коммитов; стек, manifest/lockfile, приложение и проверки отсутствуют. Ни один технический вариант ещё не принят. Продуктовые границы — [PRD](PRD.md); владельцы и зависимости — [PLAN](PLAN.md).

## Минимальный вариант для обсуждения

**Гипотеза:** если привычные инструменты команды подходят, React + TypeScript + Vite, статическое мобильное веб-демо с локальными JSON-профилями, без backend и аккаунтов. Причина: один собираемый артефакт, быстрые изменения пути и предсказуемый показ. Установку и реализацию сейчас не выполняем. Если времени на работающий путь недостаточно, допустим кликабельный прототип с теми же критериями PRD.

**Открытый вопрос:** какие инструменты уже знакомы Талгату и Тамеру и что быстрее доведёт выбранный путь до теста? Решение записать в PLAN до установки зависимостей; распределение frontend/backend не предполагается.

Предлагаемая схема демо: экран запроса → локальные фильтрация/объяснение → сравнение/профиль → явно обозначенная симуляция обращения. Данные и переводы отделены от экранов; доменная логика не зависит от UI. Никаких реальных отправок, оплат, диагнозов или хранения историй семьи в этом варианте.

## Минимальный контракт v0 — предложение, не утверждён

Перед параллельной работой разработчики фиксируют поля, значения, пустые состояния и один пример вымышленной записи. До выбора стека это описание, не требование завести отдельный сервис.

| Сущность | Минимальные поля и смысл |
| --- | --- |
| `SearchRequest` | `needCode`, `ageBand?`, `language?` (`ru`/`kk`), `area?`, `format?`, `maxPriceKzt?`. Коды потребностей и нужные фильтры уточнить после интервью; без имени ребёнка, даты рождения, диагноза и свободной истории |
| `SpecialistProfile` | `id`, `isDemo: true`, `displayName`, `specialtyCodes`, `needCodes`, `ageBands`, `languages`, `area`, `formats`, `priceKzt: number \| null`, `qualifications[]`, `availability`, `updatedAt` |
| Доверие и актуальность | `qualifications[]`: название, `checkStatus` (`selfReported`/`documentChecked`/`unknown`), `checkScope`, `checkedBy?`, `checkedAt?`; `availability`: статус (`available`/`waitlist`/`unknown`), `asOf?`. В демо все отметки и проверяющие тоже вымышлены; отсутствующий проверяющий/дата отображаются как неизвестные |
| `SearchResult` | `profileId`, `matchReasons[]`, `unknownFields[]`; объяснения основаны на полях, без процента «медицинского соответствия» |
| `Comparison` | Список `profileIds`, одинаковый порядок признаков, видимые неизвестные значения |
| `ContactPreview` | `profileId`, `mode: simulated`, `status: preview`; действие сообщает «демо: запрос не отправлен» и не собирает контакты |

`null` означает «не указано», а не ноль/бесплатно. Неизвестная доступность не считается подтверждённым местом. Предложение функций: `search(request, profiles) → results`, `compare(ids, profiles) → rows`; общий формат ошибок и пустой выдачи согласовать в T3. В коде язык казахского — `kk`, в документах обозначение RU/KZ. Точные коды, правило сортировки и поведение при неизвестных значениях — открытые вопросы контракта.

## Источник профилей, языки и данные

- **Для демо (предложение):** вручную составленный небольшой набор вымышленных профилей; достаточно вариантов для сравнения, неизвестных сведений и пустой выдачи. Владелец набора пока не назначен. Реальные имена, телефоны, фото и скопированные анкеты не использовать.
- **Для будущего MVP (гипотеза):** профили подаются специалистом с согласием, конкретные документы проверяет назначенный сотрудник/партнёр, доступность подтверждается повторно. Кто проверяет, с какой периодичностью и как обрабатывает жалобы/удаление — ещё не решено; без этого нельзя обещать актуальную проверенную базу.
- **RU/KZ:** все шаги и состояния выбранного пути, подписи фильтров, объяснения доверия и симуляции перевести. Хранить тексты отдельно; сохранение выбора при переключении языка — Should-кандидат по PRD. Ответственный за проверку казахского пока не назначен, машинный перевод без проверки не считать подтверждённым качеством.
- **Минимизация:** запрос живёт в памяти демо; нет аналитических трекеров, логирования семейных запросов или внешней передачи. Прототип должен одинаково честно показывать ограничения на обоих языках.
- **Кабинеты (решение D4 в PLAN):** регистрация необязательна, сайт работает без входа. Роли `parent` / `specialist` / `admin` в `profiles`; роль `admin` выдаётся только вручную в SQL. Специалист меняет карточку через `specialist_changes`, применяет правку организатор функцией `review_specialist_change`. О ребёнке хранится минимум (прозвище, возрастная группа, запрос, город) с отметкой согласия законного представителя; ребёнка видит только родитель. Всё закрыто RLS. **Открытый вопрос:** до работы с реальными семьями проверить требования закона РК о персональных данных (в т. ч. хранение баз ПДн граждан РК на территории РК; регион проекта Supabase не проверен), порядок удаления аккаунта и сроки хранения. До этого — только вымышленные демоданные.

## Что работает и что проверим

**Сейчас:** работает только документация. **Ожидаемое демо:** выбранные экраны и переходы, локальные данные и объяснимая фильтрация либо кликабельная имитация; контакт честно симулируется. **Будущий MVP:** реальные обращения, безопасное хранение, доступы сотрудников, согласия, обновление базы и обработка жалоб потребуют отдельного решения и оценки. Достаточность бюджета из [HACKATHON](HACKATHON.md) не доказана.

После появления кода добавить в README только реально существующие команды. Проверять настроенные сборку/типизацию/линт; критическую логику фильтров и неизвестных значений — целевыми тестами. Вручную пройти [AC1–AC6](PRD.md#критерии-приёмки-кандидата) с телефона на RU/KZ, проверить пустую выдачу, возврат, отсутствие внешней отправки. Проверяющий не должен быть автором изменения.

Перед финалом: открыть ссылку на устройстве показа, проверить доступ без аккаунта, подготовить локальный/записанный резерв показа и PDF-презентацию. После срока фиксации материалов из HACKATHON заморозить сданную версию. Лицензии, применение ИИ и честные ограничения демо включить в передаваемые материалы.
