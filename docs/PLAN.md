## Короткая задача агенту и интеграция

Перед передачей T4 разделить на задачи, каждую из которых можно проверить за один рабочий заход:

> **ID / цель:** … **Требование:** ссылка на PRD AC… или TRD. **Границы:** файлы/модули и что входит. **Приёмка:** наблюдаемый результат. **Проверка:** существующая команда или ручной сценарий. **Владелец / проверяющий:** … **Зависимости / контракт:** … **Ветка или worktree:** …

Общие файлы и интеграция принадлежат одному назначенному владельцу. Разработчики используют отдельные ветки/checkout; параллельные агенты на одной машине — отдельные worktree. Для этого в пустом Git сначала нужен согласованный начальный коммит; этот запуск коммитов и worktree не создавал. Сначала контракт и границы, затем параллельная реализация. Исследовательские read-only поручения могут идти независимо.

Существенная задача: короткий план → реализация → уместные проверки → просмотр diff → независимый просмотр вторым разработчиком/сессией → небольшая интеграция. Настроенные сборка/типизация/линт и тесты критической логики дополняются ручным мобильным проходом RU/KZ. Не выдумывать команды или результаты. После задачи достаточно обновить строку и передачу контекста; PRD/TRD меняются только при последствиях для требований/контрактов.
