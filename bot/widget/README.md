# Виджет «Подбор специалиста» (эксперимент)

Опрос из бота в одном интерактивном пузыре: Telegram-виджеты, Bot API 10.4 (`sendWidget`, `widget_query`,
`editMessageWidgetData`, `answerWidgetQuery`). По умолчанию выключен: без `WIDGETS_ENABLED=1` бот работает как раньше.

| Файл | Что это |
|---|---|
| `quiz.html` | Сам виджет: 4,2 КБ, 2093 Б после zlib-9 (лимит 4096) |
| `index.js` | `/widget` (только личка), обработка `widget_query`, протокол — в шапке файла |
| `selftest.js` | Офлайн-проверка на настоящем `bot/index.js` без сети и токена |
| `probe.js` | Пробный `sendWidget` с `<b>hello</b>` по `.env.test` |

## Запуск

```sh
cd bot && npm ci
node widget/selftest.js        # с флагом
node widget/selftest.js off    # без флага: поведение прежнее
WIDGETS_ENABLED=1 node index.js            # с .env в корне
node index.js --env .env.test              # другой файл окружения (WIDGETS_ENABLED=1 можно в нём)
```

`.env.test`: `BOT_TOKEN`, `WIDGETS_ENABLED=1`; для тестового окружения Telegram ещё
`BOT_API_BASE=https://api.telegram.org/beta` и `BOT_TEST_ENV=1`. Один токен — один поллер: не запускайте локально
бот на токене, который уже работает в проде.

## Протокол

| `chatData` | `publicData` | Запросы → ответ |
|---|---|---|
| `{s,a,t,f}`: шаг (1–3 вопросы, 4 результат), индексы возраста, тем, формата | `{o:{a,t,f},u,r?,n?}`: подписи вариантов, username бота, рекомендация `[[название, описание]]`, пояснение. Пересылка видит только это | `<действие>[:N]\|s,a,t,f`: `a:N`, `t:N`, `n`, `f:N`, `b`, `r`, `l` → `{c,p}`, `{m}` или `{err}` |

Состояние приходит в самом запросе, поэтому бот его не хранит. «Оставить заявку» (`l`) переносит ответы
в обычный поток заявки сообщением в чате. Город в виджете не спрашивается: в виджете нет полей ввода.
